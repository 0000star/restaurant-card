\# Мои рестораны\
\
Личный трекер посещённых ресторанов и кафе. Один пользователь, данные
хранятся локально в браузере.\
\
\## Цель\
\
Быстро записать, где был, что понравилось и сколько это стоило, и потом
легко найти запись по оценке, дате или кухне.\
\
\## Границы MVP\
\
\*\*Входит:\*\*\

- добавление заведения: название, кухня (из списка или свой вариант),
  город, адрес, дата визита;\
- оценка 1--5 и текстовый комментарий;\
- средний чек (в рублях) и понравившиеся блюда;\
- список записей, редактирование и удаление;\
- фильтрация и сортировка по оценке, дате, кухне;\
- сохранение в localStorage (данные переживают перезагрузку страницы).\
  \
  \*\*Не входит:\*\*\
- соцфункции и шаринг;\
- интеграции с внешними API;\
- мобильное приложение;\
- оплата;\
- бэкенд, авторизация, несколько пользователей.\
  \
  \## Ключевые решения\
  \
- Одна запись = один визит. Повторный визит в то же место --- новая
  запись.\
- Валюта одна --- рубли.\
- Город и адрес --- отдельные поля (задел под карту).\
- Слой хранения изолирован (\`storage.ts\` + \`use-restaurants.ts\`),
  чтобы заменить localStorage на Supabase без переписывания UI.\
  \
  \## Этапы развития\
  \

1. \*\*MVP\*\* --- всё из раздела «Входит». Деплой на Vercel.\
2. \*\*Статистика\*\* --- средняя оценка, топ кухонь, траты по месяцам.\
3. \*\*Карта\*\* --- точки на карте по city/address.\
4. \*\*Supabase\*\* --- БД, авторизация, storage (фото), миграция данных
   из localStorage.\
5. \*\*Экспорт/импорт\*\* --- JSON-бэкап.\
   \
   \## Критерии готовности MVP\
   \
   Приложение запускается, можно добавить ресторан, он появляется в списке,
   данные сохраняются после перезагрузки, \`npm run build\` и \`npm run
   lint\` проходят без ошибок.Í
