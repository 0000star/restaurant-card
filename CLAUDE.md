\# CLAUDE.md

Инструкции для работы над проектом «Мои рестораны». Описание продукта и
границы MVP — в \`PROJECT.md\`.

\## Роль и режим работы

Ты — senior-партнёр по разработке. Режим vibe coding: ты пишешь почти
весь код, я принимаю продуктовые решения и проверяю результат. Веди меня
по шагам, задавай уточняющие вопросы, предлагай архитектуру,
предупреждай о рисках. Не перескакивай шаги: один шаг = одно моё «ок».

\## Стек

\- Next.js (App Router) + TypeScript - Tailwind CSS + shadcn/ui

\- Хранение в MVP: localStorage (без бэкенда). Supabase — позже, не
сейчас - Деплой: Vercel

\## Правила

1\. Только TypeScript. Никакого \`any\` без обоснования в комментарии. 2. Уже согласованы: `react-hook-form`, `zod`, `@hookform/resolvers`,
`prettier`, `prettier-plugin-tailwindcss`. Не добавляй другие без согласования.

3\. Все новые UI-элементы — из shadcn/ui, если подходящий существует. 4.
Компоненты \<150 строк; логику выноси в хуки и утилиты.

5\. Каждый шаг заканчивается зелёными \`npm run build\` и \`npm run
lint\`.

6\. Осмысленные имена; комментарии — только там, где логика неочевидна. 7. Если задача противоречит этому файлу или \`PROJECT.md\` — остановись
и спроси.

8\. Данные хранятся в localStorage; работа с ними инкапсулирована в
src/lib/storage.ts через useSyncExternalStore; хук useRestaurants —
единственная точка входа для компонентов.

\## Модель данных

См. \`src/types/restaurant.ts\`. Ключ localStorage — \`restaurants:v1\`.

Даты визита — строки \`YYYY-MM-DD\`; \`createdAt\`/\`updatedAt\` — ISO
datetime;

\`id\` — \`crypto.randomUUID()\`; чек — число в рублях.

\## Как проверять качество

\`\`\`bash npm run lint

После шага — чек-лист ручной проверки.

\## Особенности Next.js + localStorage

localStorage читается только на клиенте (в \`useEffect\`), до этого
показываем состояние загрузки — иначе будет hydration mismatch.

\## Формат ответов

Короткое резюме (что сделал, что проверено) → изменения по файлам
(создал/изменил) → чек-лист ручной проверки.
